# Ultrathink

Ruo 사용자 확장. 기존 `/ultramode` 및 `/fast`와 독립적으로 요청 한 건에만 적용합니다.

## 사용법
- `/ultrathink <질문 또는 작업>`: 바로 실행
- `/ultrathink`: 다음 일반 입력에 1회 적용
- `/ultrathink off`: 다음 입력 예약 해제 (진행 중 작업은 Esc로 취소)
- 설치 후 실행 중인 Ruo에서는 `/reload` 또는 재시작 필요

## 동작
1. 메인 에이전트가 난이도와 불확실성에 따라 2~8개의 서로 다른 역할을 선택합니다.
2. 선택된 역할을 독립된 Ruo 프로세스에서 모두 병렬 실행합니다.
3. 서브에이전트는 현재 모델을 사용하며 추론 지원 모델은 high로 실행합니다.
4. 서브에이전트 도구는 read/grep/find/ls로 제한하고 다른 확장 및 재귀 위임을 비활성화합니다.
5. 메인이 결과의 근거, 반례, 의견 차이를 검토하고 최종 답변을 종합합니다.
6. 구현 요청인 경우 파일 변경은 추론 결과를 검토한 뒤 메인이 수행합니다.

## 제한과 안전
- 정답을 보장하지 않으며 다수결만으로 정확하다고 판단하지 않도록 지시합니다.
- 에이전트당 5분 제한, 사용자 취소 전파, 오류 및 부분 성공 구분, 임시 파일 정리를 지원합니다.
- 선택한 수만큼 모델 요청이 늘어나므로 토큰 사용량/비용 및 API 동시 요청 제한을 고려하세요.
- 메인은 필요한 대화 문맥을 명시적으로 전달해야 합니다. 서브에이전트는 대화 이력을 자동 상속하지 않습니다.
- 읽기 전용 도구 제한은 파일 수정/명령 실행을 막지만 운영체제 파일 읽기 샌드박스는 아닙니다.
- 이미지 데이터는 서브에이전트에 직접 전달하지 않습니다. 메인이 필요한 관찰 내용을 공유해야 합니다.
- 추가 의존성 설치 없이 Ruo 확장 런타임과 Node 기본 모듈을 사용합니다.

## 검증
실제 확장 로더 등록과 로컬 모의 프로세스 기반 오프라인 검증을 통과했습니다.
검증 범위: 역할 수/중복 검증, 실제 병렬 프로세스, 읽기 전용 옵션, 0600 임시 파일,
최종 JSON 처리, 제공자 오류, 부분 성공 경고, 시간 초과, 취소, 실행 실패,
메인 선택 개수 적용, 진행 표시, 일회성 해제, 문맥 정리, 입력 이미지 보존, 1회 보완 요청.
실제 모델 API를 이용한 종단간 추론 검증은 수행하지 않았습니다.
